# MCAT Time Allocation Dashboard Guide

This repository includes a Streamlit dashboard that turns one full-length exam into **timing decisions you can apply on your next practice session**.

Use this README as a walkthrough for interpreting **each part of the dashboard**.

---

## Quick start

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py
```

Then open the URL shown by Streamlit (usually `http://localhost:8501`).

---

## What this dashboard is designed to answer

The dashboard is not a content-review tool. It answers execution questions:

- Where does extra time stop improving accuracy?
- Which sections should have stricter hard caps?
- Are you front-loading time early in a section?
- How many questions are "slow + wrong" (high time, no payoff)?
- What are the highest-impact rules for the next 48–72 hours?

---

## Data assumptions behind all charts

The app loads section CSVs from `data/exam_1`, normalizes them, and computes section-level analyses.

Core fields used in interpretation:

- `question_index`: question order in section
- `is_correct`: whether the question was correct
- `time_spent_sec`: time spent per question in seconds
- `section`: `CP`, `CARS`, `BB`, or `PSB`

## Dashboard interpretation guide (top to bottom)

### 1) Header metrics (top row)

You will see four KPIs:

1. **Total Questions**  
   How many questions are included in the loaded exam.

2. **Overall Accuracy**  
   Percent correct across all sections.

3. **Median Time / Q**  
   Typical (middle) time per question across all sections.

4. **Top Leak Sections**  
   Sections ranked as the largest execution point leaks by synthesis logic.

**How to use it:** Treat this row as a snapshot only. Your decisions should come from the module-level evidence below.

---

### 2) Phase 1 Modules — per-section diagnostics

Each section (`BB`, `CARS`, `CP`, `PSB`) gets the same four modules.

#### Module 1: Time–Accuracy Curve (quartiles)

Chart contents:
- Quartiles `Q1` (fastest) through `Q4` (slowest)
- `mean_time_sec` and `accuracy_pct` for each quartile

Interpretation:
- If `Q4` accuracy is not better than `Q3`, you likely have **diminishing returns** at higher times.
- The "peak quartile" indicates where your best speed/accuracy balance occurred.

Action bias:
- Use this module to justify speeding up above your peak-accuracy time band.

#### Module 2: Time Cap Derivation

Chart contents:
- Two bands: `<= cap` and `> cap`
- Accuracy and question count in each band

Interpretation:
- Hard cap is derived from section median time (`median * 1.2`, rounded for messaging).
- If above-cap accuracy is not better, the cap is considered empirically justified.

Action bias:
- If cap is justified, treat it as a non-negotiable hard stop.
- If not justified, keep a provisional cap and re-check with the next exam.

#### Module 3: Question Order Drift

Chart contents:
- Rolling average time by question order
- Rolling accuracy by question order

Interpretation:
- Compare early/middle/late pacing behavior.
- A front-loading flag means early questions are taking more time without clear accuracy benefit.

Action bias:
- Aim for steadier pacing when early overspending appears.

#### Module 4: Slow–Wrong Execution Sink

Chart contents:
- Count of `Slow+Wrong` vs `Other`
- Slow threshold is section `p75(time_spent_sec)`

Interpretation:
- "Slow + wrong" are questions where time investment did not produce points.
- A guardrail (count threshold) determines whether this is large enough to prioritize immediately.

Action bias:
- High slow+wrong volume = train faster abandon/guess decisions.

---

### 3) Phase 2 — Ranked Point Leaks (table)

Columns:
- **Section**
- **Impact (%)**
- **Cap Justified**
- **Slow+Wrong Guardrail**

Interpretation:
- This ranks where behavior changes are likely to produce the biggest score return.

Action bias:
- Start intervention from top-ranked leak to avoid trying to fix everything at once.

---

### 4) Per-Section Non-Negotiable Rules (expanders)

Each section includes rule bullets generated by synthesis.

Interpretation:
- These are explicit, testable execution constraints (e.g., cap rules, pacing directives).

Action bias:
- Convert each rule into a single-session checklist item.

---

### 5) Phase 3 — 48–72 Hour Practice Prescriptions

Per section, you get:
- Session duration
- Question target
- One single enforced rule

Interpretation:
- The plan intentionally enforces one behavior at a time to avoid cognitive overload.

Action bias:
- Evaluate these sessions by cap violations and time variance first (not raw score first).

---

### 6) Recommendations (qualitative)

This section gives behavior-first reminders (commit to caps, avoid rabbit holes, debrief trigger misses).

Interpretation:
- These are operating principles that support the numeric findings above.

---

### 7) Phase 4 — Core Message

A short, confidence-directing statement generated from synthesis.

Interpretation:
- Use this as a mental reframe: time discipline is a scoring strategy, not just stress management.

---

### 8) Section Aggregates (bottom table)

Section-level summary stats, including accuracy.

Interpretation:
- Use for context, not rule derivation.
- Module-level outputs are the stronger source for actionable decisions.

---

## Practical workflow for a student using this dashboard

1. Read **Top Leak Sections** and **Ranked Point Leaks** first.
2. For your highest-leak section, inspect Modules 1–4 in order.
3. Write down one non-negotiable rule for your next session.
4. Run one 30–45 min block with only that rule enforced.
5. Debrief only timing trigger failures (when you stayed too long).
6. Repeat with next section after one successful block.
